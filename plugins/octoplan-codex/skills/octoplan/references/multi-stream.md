# Multi-stream coordination

Read this only for more than one work stream. Multi-stream work keeps the same Brief, Plan, Delivery, authority, review, and closure semantics. It adds graph breadth, not a second protocol.

## Select the topology

Use several streams only when the confirmed outcome contains independently closable results, distinct delivery targets or gates, real parallel ownership, or separate cadences. Link them to one existing or justified goal only when they advance one shared destination. Give every stream its own definition of success. If one definition covers all work, use one stream.

Record cross-stream dependencies with a rationale and the exact produced state the dependent stream needs. Do not use priority, dates, or supervisor memory to imply order. Keep tasks in the stream that owns their deliverable and evidence.

## Plan and review the whole graph

The Plan shows one plain-language line per step across all streams and names which streams can advance independently. Review receipts name every task and revision reviewed across the streams.

Plan review covers the complete graph. Add integration and write-conflict checks for shared schemas, migrations, generated files, wording surfaces, repositories, services, and publication targets. Do not parallelize work whose outputs shape one another's contract or write the same surface.

## Supervise one ready frontier

The one supervisor named in the stream Decision selects the ready frontier across every active stream. Apply the saved route and review floor per task. A blocked stream or gate stops only downstream work; continue every independent ready branch within the recorded mandate and capacity.

Persist progress and evidence on each owning task. Use cross-stream comments only as links to authoritative receipts, never as a copied aggregate state. Recompute the ready frontier from current Octopad dependencies after every accepted result or material event.

## Close precisely

A stream may close when its definition of success and required gates are proved, even while independent streams continue. Close the shared outcome only when integrated evidence covers every required stream and cross-stream seam. Report each stream with a supported state (`built`, `reviewed`, `merged`, `applied`, `verified`, `released`, `accepted`) or a domain equivalent.

A split, merge, new stream, removed stream, or changed cross-stream dependency is a material Plan change. Stop only affected work, update the graph, run the applicable fresh review floor, and obtain a new Plan go when authority or disclosed consequences change.
